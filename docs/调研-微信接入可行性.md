### 1.4 网络环境（这决定了 GitHub 能不能用）

实测发现，GitHub 之所以在本机可用，**完全依赖 Watt Toolkit（Steam++）加速器**：

```
监听进程 : Steam++.Accelerator (PID 14972) 监听 0.0.0.0:80 与 0.0.0.0:443
hosts    : # Steam++ Start ... # Steam++ End 段内把以下域名指向 127.0.0.1：
           github.com, api.github.com, objects.githubusercontent.com,
           raw.githubusercontent.com, github.githubassets.com, github.io, huggingface.co ...
```

| 域名 | DNS 解析结果 | 含义 |
|---|---|---|
| `github.com` | `127.0.0.1` | 被 hosts 重定向 → 由加速器代答 |
| `api.github.com` | `127.0.0.1` | 同上 |
| `objects.githubusercontent.com` | `127.0.0.1` | 同上 |
| `raw.githubusercontent.com` | `127.0.0.1` | 同上，但**实测连接失败**（加速器未覆盖） |
| `release-assets.githubusercontent.com` | `185.199.108‑111.133`（真实 Fastly IP） | **不走加速器**，大文件走这里直连 |

**结论：**
1. 之前记录的"`api.github.com` → 502 被挡、不可用"**在当前环境下已经不成立**——实测返回 **200**，能正常拉到 release 列表。当时大概率是加速器未开启或状态异常。
2. 运行 `find_wechat_4108107.ps1` 前**必须确保 Watt Toolkit 已启动且 GitHub 加速已开启**，否则 `github.com` 会指向无人监听的 `127.0.0.1`，所有请求直接连接失败。脚本已内置这项自检并会给出中文提示。
3. 233 MB 的安装包由 `release-assets.githubusercontent.com` 直接提供，**不经加速器**，属于直连 Fastly CDN。

## 2. 三个脚本说明

> ⚠️ **重要：本机没有安装 PowerShell 7。**
> 实测 `Get-Command pwsh` 返回 False，本机只有 Windows PowerShell **5.1**（`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`）。
> 所以下面所有命令都请用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File …` 的形式。
> （三个脚本都已实测在 PowerShell 5.1 下语法解析通过，`-DryRun` 也实际跑通了。）
> 另一个相关坑：三个 `.ps1` 脚本都保存为 **UTF-8 with BOM**，这是必须的 ——
> PowerShell 5.1 读取无 BOM 的 `.ps1` 会按 ANSI(GBK) 解码，中文提示会全变乱码。
> 如果你后续用编辑器改这些脚本，**务必保持 BOM**。

### 2.1 `tools/setup_python312.ps1` —— Python 3.12 微信桥环境

**用途**：下载 Python 3.12.10 → 用户级静默安装到 `.python312` → 建 `.venv312` → 安装 `requirements-wechat.txt` → 打印版本验证。

| 项目 | 内容 |
|---|---|
| 用法 | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\setup_python312.ps1`<br>`… -DryRun`（只预演，不动任何东西）<br>`… -Force`（忽略已有产物重做） |
| 下载源 | `https://www.python.org/ftp/python/3.12.10/python-3.12.10-amd64.exe`（实测 200，**26,964,224 字节**） |
| 安装位置 | `<项目目录>\.python312` |
| 安装参数 | `/quiet InstallAllUsers=0 TargetDir="…\.python312" Include_pip=1 Include_launcher=0 PrependPath=0 Include_test=0 /norestart` |
| venv | `<项目目录>\.venv312` |
| 幂等 | 安装包按字节数校验后跳过；`.python312\python.exe` 可用且为 3.12 则跳过；`.venv312` 已存在则跳过 |
| 安全边界 | **不修改系统/用户 PATH**（`PrependPath=0`、不装 launcher、全程用绝对路径）；**不弹 UAC**（`InstallAllUsers=0`）；不改注册表 |
| 失败处理 | 每步失败打印可读中文错误并 `exit 1`，且提示修复后重跑（已完成步骤会自动跳过） |

**风险**
- 低。唯一注意：`TargetDir` 含中文路径，Python 官方安装器支持，但若中途残留半个目录会导致重装失败 → 脚本会提示先删除 `.python312`。
- `pip install` 需要联网 PyPI。实测 `https://pypi.org/simple/wxauto4/` 返回 **200** 可用；若遇到超时，脚本报错信息里已附清华镜像的备用命令。
- 该脚本会**真的联网下载并安装 Python**，请在你确认后再运行；`-DryRun` 可先看清全部动作。
- ⚠️ **实测下载速度偏慢**：观察脚本真实运行时，从 `python.org` 拉取 26.9 MB 的安装包速率约 **16 KB/s**
  （6 秒内 `.partial` 只增长 98 KB）。按此速率**需要 20–30 分钟**才能下完，属正常但要有耐心。
  脚本为此把单次读写超时设为 5 分钟（`ReadWriteTimeout = 300000`），**不会因为慢而被误判为超时失败**。
  如果你等不及，可以手动用下载工具（或国内镜像）取同一文件，放到 `tools\downloads\python-3.12.10-amd64.exe`
  —— 脚本检测到该文件**字节数等于 26,964,224** 就会直接跳过下载。
- ⚠️ **不要并发运行同一个脚本**：脚本用固定的 `<文件>.partial` 作临时名，
  两个实例同时跑会互相踩踏。请确认上一次已结束（`.partial` 已被改名或删除）再运行。

## 3. 微信 4.1.13.65 → 4.1.8.107 降级完整人工步骤

> **本节必须由人工逐步执行。脚本不会代做任何一步。**
> 请按顺序执行，不要跳步。全程建议开着 §3.1 的备份。

### 3.1 第一步：备份聊天记录目录（**不可跳过**）

实测确认当前活动数据目录为 `%USERPROFILE%\Documents\xwechat_files`（0.72 GiB，3191 个文件）。

```powershell
# 1) 确认目录存在（实测 = True）
$src = Join-Path $env:USERPROFILE 'Documents\xwechat_files'
Test-Path $src

# 2) 确认微信已完全退出（下面这条应输出 0 个进程）
(Get-Process -Name Weixin -ErrorAction SilentlyContinue).Count

# 3) 用 robocopy 完整备份（/E 含子目录含空目录，/COPY:DAT 保留时间戳）
$dst = 'D:\NekoPal-backup\xwechat_files_20261003'
robocopy $src $dst /E /COPY:DAT /R:1 /W:1 /MT:8
# robocopy 退出码 0–7 都算成功；>=8 才是真失败
```

补充建议：
- 再用微信自带的 **设置 → 聊天 → 聊天记录迁移与备份**，把记录备份到另一台设备或移动硬盘（这是唯一被官方支持的备份途径）。
- 顺便留意 `D:\xwechat_files`（旧的 0.08 GiB 遗留目录），不是主目录，可不动。

**还要额外下载一份"回滚安装包"（强烈建议）：**
如 §4.1.1 所述，GitHub 归档里**连你当前的 4.1.13.65 都有**。请在卸载之前先把它也存好：

```powershell

irm "https://api.github.com/repos/SiverKing/wechat4.0-windows-versions/releases/tags/v4.1.13.65" |

```
然后用浏览器或 `find_wechat_4108107.ps1` 的同款方式把该 exe 下载到 `D:\NekoPal-backup\`。
这样万一降级后发现不能用，你能**立刻装回 4.1.13.65**，不用指望腾讯官方 CDN 还留着。

### 3.4 第四步：如何忽略强制升级提示

> ⚠️ **诚实披露**：我没有真实安装 4.1.8.107（本次调研明令禁止执行安装程序），
> 因此**下面这一节是"通用做法 + 风险评估"，不是我在本机验证过的结果**。
> 微信的升级策略会随版本变化，请以你实际看到的行为为准。

微信 4.x 的升级提示通常有三种强度：可关闭的提示气泡 → 弹窗（可稍后） → **强制升级窗口（关不掉）**。按代价从低到高：

| 做法 | 具体操作 | 有效性 | 风险 |
|---|---|---|---|
| **① 就是不点**（先试这个） | 升级弹窗点"稍后"/"取消"/右上角 ×，继续用 | 对付"提示型"有效；"强制型"无效 | 无 |

### 3.5 第五步：风险提示 —— 聊天记录可能不同步

**这是本次改造最大的功能性风险，请务必知情：**

1. **数据库格式可能不向后兼容。** 微信 4.x 的本地数据在 `xwechat_files\<wxid>_xxxx\db_storage`。4.1.13.65 写入的库 schema 版本可能**高于** 4.1.8.107 能识别的版本。降级后可能出现：
   - 部分或全部历史聊天记录**看不到**
   - 提示需要重新同步 / 数据库损坏
   - 极端情况旧版客户端启动即报错
   > 数据通常**仍在磁盘上（已备份）**，只是旧客户端读不出来；但**能否回退读取无法保证**。
2. **服务器不会帮你补齐。** 微信服务器只暂存未接收的消息，不会把历史记录重新下发。降级**不会**自动合并任何记录。
3. **部分消息类型可能丢失**：新版本才支持的消息/文件格式，旧版可能无法解析。
4. **降级后新产生的记录**，再升回 4.1.13.65 时也可能遇到同样的反向兼容问题。**降级不是无损可逆操作。**
5. **最坏情况：无法登录。** 如果腾讯对 4.1.8.107 设定了最低版本限制，你会看到"当前版本过低，请升级后使用"而**根本进不去**——那么这次降级的唯一结果就是你把微信换成了旧版，还得再装回去。
   > 这也是为什么 §3.1 的备份**绝对不能省**。

**缓解建议**：如果有条件，**先用小号在另一台电脑或虚拟机里试一次**完整流程（降级 → 登录 → wxauto4 连通性），确认可行再动主力机的微信。

## 5. 可行性结论（诚实评估）

### 5.1 拆分来看，"可行性"其实是两个独立的问题

| 子问题 | 结论 | 依据 |
|---|---|---|
| **A. 能不能拿到可信的 4.1.8.107 安装包？** | ✅ **能，而且可信度很高** | 两个独立归档 + GitHub 官方 API 的 SHA256 三方一致；字节数一致；PE 头合法；可溯源到腾讯原始 URL |
| **B. 装上之后能不能正常用、会不会被强制升级？** | ⚠️ **未知，中等偏高风险** | 本次**明令禁止执行安装程序与改动微信**，因此这两点**无法在本次调研中验证** |

### 5.2 对 B 的逐条风险判断

| 风险 | 严重度 | 说明 |
|---|---|---|
| 旧版被拒绝登录（"版本过低"） | **高** | 一旦发生，降级方案**直接失败**，只能装回新版。这是整条路的**头号杀手** |
| 聊天记录不可读 / 需重新同步 | **中高** | 已备份，数据不丢，但**可能读不出来**，见 §3.5 |
| 强制升级窗关不掉 | 中 | 可用防火墙规则缓解（§3.4 ②），但非 100% 保证 |
| wxauto4 免费版的真实版本上限 | 中 | 用户记录为"最高 4.1.8.107"，但 **wxauto4 的 README 却写着"目前仅适用于微信 4.0.5"**（该 README 版本徽章为 40.1.1，明显未随包更新）。两者矛盾，**需以装好后的实测为准** |
| 依赖本机 GitHub 加速器 | 低中 | 加速器不开 → GitHub 全部不可达；但**已下载的文件不受影响**，且 233MB 走 Fastly 直连 |
| 微信 4.x UI 变化导致自动化失效 | 中 | wxauto4 依赖 UI 自动化（窗口可见、不能最小化），4.1.8.107 之后微信 UI 仍在演进 |

### 5.3 一句话总结

> **"能不能搞到 4.1.8.107" —— 能，证据扎实（SHA256 可校验、来源可溯源）。**
> **"降级这条路值不值得走" —— 建议先做一次零风险的可行性验证：用小号 + 另一台电脑/虚拟机，按 §3 走完整流程。**
> 如果验证通过，再动主力机；如果连登录都过不去，就果断转向 §6 的替代方案。

## 6. 替代方案（按推荐度排序）

### 方案 1（**最推荐先评估**）：改用 wxautox4 Plus，**不降级微信**

- 实测 PyPI：`wxautox4 41.2.1`，`requires_python = <3.14,>=3.9`（故 **Python 3.12 环境仍然要建**，`setup_python312.ps1` 照样有用）。
- 用户记录称 Plus 版支持 **Python 3.9–3.13、微信最高 4.1.13**。
- **关键动作**：先向 wxautox4 作者确认 **它是否支持你当前的 4.1.13.65**（4.1.13.65 略高于记录的 4.1.13，需核实）。
- **优势**：**完全不用碰微信客户端**，零降级风险、零聊天记录风险、零强制升级问题。代价是付费激活码。
- **结论**：如果它支持 4.1.13.65，**这条路严格优于降级**，应该优先走。

### 方案 2：改走**企业微信机器人**推送

- 本机**已安装企业微信 5.0.9.6029**（`D:\WXWork`），基础设施现成。
- 企业微信有**官方支持**的群机器人 Webhook、应用消息 API，**不依赖 UI 自动化、不依赖客户端版本、不会被强制升级打断**。
- **劣势**：触达的是企业微信而非个人微信；"猫娘双向对话"体验与个人微信不同（但群机器人"接收+回复"是可行的）。
- **结论**：**工程上最稳、最不容易崩**的方案。若"必须用个人微信"不是硬性要求，强烈建议认真考虑。

### 方案 3：保留 4.1.13.65，只做**单向**推送

- 不降级、不装 wxauto4，只保留"猫娘主动发消息"的能力（或干脆不要微信通道）。
- 放弃"双向对话"里的"接收用户消息"能力。
- **结论**：最保守、零风险，但功能缩水。

### 方案 4：降级 + wxauto4 免费版（**本任务原定路线**）

- 见 §3 与 §5。**前提是先完成 §5.3 的小号验证。**

### 方案 5（**不推荐**）：使用第三方软件站/网盘镜像

- 本次探测**没有找到**任何境内软件站提供 4.1.8.107。
- 即使找到，也无法像 GitHub 归档那样做 **SHA256 溯源比对**，**无法排除被捆绑木马/后门的风险**（微信安装包是木马投放的重灾区）。
- **结论**：除非能拿到与 `b79aa3fd…62b90` 完全一致的哈希，否则**不要用**。
